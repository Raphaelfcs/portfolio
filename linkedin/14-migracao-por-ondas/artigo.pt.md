# Migração por ondas para EKS

*Integradores migrados em ondas, com namespace próprio, fila com DLQ, banco por serviço e acesso externo por Lambda.*

Raphael Santos · 3 min de leitura · Plataforma AWS de uma operadora de saúde (2024)

![Migração por ondas para EKS](https://raphaelfcs.github.io/portfolio/artigos/img/migracao-por-ondas-pt-1.webp)

> **Em resumo:** Migrar para Kubernetes em uma onda só é aposta. Em ondas é engenharia.

## O problema

Sistema corporativo com dezenas de componentes indo para o EKS.

## A solução

Ondas agrupadas por dependência, segredos centralizados antes da primeira onda e critério de saída claro para cada uma.

### Migração por ondas para EKS

1. Front-end no CloudFront.
2. APIs publicadas no API Gateway.
3. Cada integrador ganha seu namespace.
4. Comunicação assíncrona por fila com DLQ.
5. Banco por serviço, segredo no Secrets Manager.
6. Parceiro externo consome a fila via Lambda.

> **Nota:** Ondas agrupadas por dependência; segredos centralizados antes da primeira onda.

## O código

```hcl
module "kms_key" {
  source = "git::https://github.com/Raphaelfcs/automacao_terraform.git//aws/kms-key"

  name_prefix             = local.name_prefix
  deletion_window_in_days = 7
  tags                    = local.tags
}

module "vpc" {
  source = "git::https://github.com/Raphaelfcs/automacao_terraform.git//aws/vpc"

  name_prefix        = local.name_prefix
  cidr_block         = "10.20.0.0/16"
  azs                = ["sa-east-1a", "sa-east-1b"]
  single_nat_gateway = true
  eks_cluster_name   = "demo-dev"
  tags               = local.tags
}
```

### FinOps: onde está o custo

| Componente | O que pesa | Alavanca |
|---|---|---|
| aws/eks-cluster | nós do EKS (EC2) e o control plane por cluster | autoscaling de nós (Karpenter/Cluster Autoscaler), Spot para cargas tolerantes e Savings Plans para a base |
| aws/rds-instance | classe da instância e Multi-AZ do RDS | dimensionar pela métrica real, reserva para PRD e parar HML/DEV fora do horário |
| aws/vpc | NAT Gateway por AZ e tráfego que passa por ele | um NAT só em DEV e VPC endpoints para S3/ECR tirarem tráfego do NAT |
| aws/ecr | imagens antigas acumuladas no ECR | lifecycle policy mantendo só as últimas N imagens por repositório |

No repositório, aws/tag-compliance, aws/finops-cost-report, aws/cur-focus-export e aws/instance-scheduler fecham o ciclo: tags obrigatórias, relatório de custo, export CUR/FOCUS e agenda de desligamento.
