# Asynchronous regulatory reports

*Asynchronous request with a queue, Lambda, SOAP integration with an OCI legacy system and delivery through a signed link.*

Raphael Santos · 3 min read · AWS platform of a health insurer (2024)

![Regulatory report generation](https://raphaelfcs.github.io/portfolio/artigos/img/relatorios-regulatorios-en-1.webp)

> **TL;DR:** Regulatory reports have deadlines. Asynchronous design helps you meet them.

## Problem

Reports required by the regulator, generated by hand and at risk of being late.

## Solution

The API records the request, a queue decouples, Lambda calls the SOAP legacy system on OCI and stores the file in S3. The status call returns "processing" or a signed link.

### Regulatory report generation

1. System requests the report (POST).
2. Service records the request and publishes it.
3. Lambda consumes the request.
4. Calls the SOAP legacy on OCI to build the report.
5. Saves the file to S3 and updates the state.
6. Status call (GET) returns "processing" or the signed link.

### FinOps: where the cost is

| Component | What drives cost | Lever |
|---|---|---|
| aws/s3-bucket | S3 storage and old object versions | lifecycle to IA/Glacier and expiration of noncurrent versions |
| aws/lambda-function | function duration × memory | tune memory with Power Tuning and use arm64 |
| aws/sqs-queue | queue requests | long polling and batch sends |
| aws/api-gateway-lambda | API Gateway requests | HTTP API instead of REST API when the extra features are not needed, plus edge caching |

In the repository, aws/tag-compliance, aws/finops-cost-report, aws/cur-focus-export and aws/instance-scheduler close the loop: mandatory tags, cost report, CUR/FOCUS export and shutdown schedule.
