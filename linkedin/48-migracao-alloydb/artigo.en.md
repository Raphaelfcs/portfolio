# Migration to AlloyDB

*AlloyDB with backup, archiving to Cloud Storage and an API for legacy data.*

Raphael Santos · 3 min read · Network, gateways and data on Google Cloud (2024)

![Migration to AlloyDB](https://raphaelfcs.github.io/portfolio/artigos/img/migracao-alloydb-en-1.webp)

> **TL;DR:** Migrating to AlloyDB with a way back.

## Problem

Transactional database needing more performance without rewriting the app.

## Solution

AlloyDB as the target, continuous backups, archiving to Cloud Storage and a dedicated API to query old data.

### Migration to AlloyDB

1. App points to AlloyDB (PostgreSQL compatible).
2. Continuous backups.
3. Old data archived to Cloud Storage.
4. Dedicated API queries the archive.

### FinOps: where the cost is

| Component | What drives cost | Lever |
|---|---|---|
| gcp/vpc-network | Cloud NAT and cross-zone/region traffic | Private Google Access and keep traffic in the same region |
| gcp/project-foundation | cost starts in projects without an owner | labels on every project (the module already applies them) and a budget alert in Billing |
