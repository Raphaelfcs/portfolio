# BFF for external partners

*Public API with an authorizer and a BFF that calls internal services without opening the network.*

Raphael Santos · 3 min read · AWS platform of a health insurer (2024)

![BFF for external partners](https://raphaelfcs.github.io/portfolio/artigos/img/bff-acesso-externo-en-1.webp)

> **TL;DR:** Exposing an internal service to partners without opening the network.

## Problem

External partners needing services that only existed on the internal network.

## Solution

A BFF published through API Gateway, with its own contract, an authorizer and private access to the internal service. Internal services stayed internal.

### BFF for external partners

1. Partner calls the public API.
2. Authorizer validates the SSO token.
3. BFF exposes a partner-specific contract.
4. BFF calls the internal service in the cluster.
5. Service reaches the private database.
6. Replica and snapshots protect the data.

### FinOps: where the cost is

| Component | What drives cost | Lever |
|---|---|---|
| aws/rds-instance | RDS instance class and Multi-AZ | right-size from real metrics, reserve PRD and stop HML/DEV after hours |
| aws/vpc | NAT Gateway per AZ and the traffic it processes | a single NAT in DEV and VPC endpoints for S3/ECR to keep traffic off the NAT |
| aws/lambda-function | function duration × memory | tune memory with Power Tuning and use arm64 |
| aws/ecr | old images piling up in ECR | lifecycle policy keeping only the last N images per repository |

In the repository, aws/tag-compliance, aws/finops-cost-report, aws/cur-focus-export and aws/instance-scheduler close the loop: mandatory tags, cost report, CUR/FOCUS export and shutdown schedule.
